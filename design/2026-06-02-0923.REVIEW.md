# 2026-06-02 09:23 Security and Performance Review Plan

## Purpose

This document converts the external security and performance review into an
implementation plan for OxideBBS. It is intentionally prescriptive. Coding
agents should implement the tasks as written, in phase order, without inventing
policy, thresholds, schemas, or alternative security models.

The source review raised forty findings. This plan preserves those finding
numbers so future work can be traced back to the original review.

## Agent Rules

Agents implementing this plan MUST follow these rules:

1. Do phases in order unless the user explicitly asks for a different phase.
2. Do not change thresholds, defaults, table names, config names, or policies
   defined here without a new user instruction and ADR update.
3. Keep each phase as a separate logical change.
4. Add focused tests in the same phase as the implementation.
5. Update docs and config examples in the same phase as behavior changes.
6. Run `./scripts/dev-check.sh` before declaring any phase complete.
7. Do not add dependencies unless the phase explicitly says to add one. No phase
   in this plan currently requires a new dependency.
8. Do not replace DecentDB or add another datastore.
9. Do not weaken existing door command validation.
10. Do not make remote caller UI Unicode-first; caller output remains
    ANSI/CP437 byte-oriented.

## ADRs Created For This Plan

The following ADRs define decisions that agents must implement rather than
re-decide:

If an implementation phase discovers that an ADR cannot be implemented as

## Phase 1: Telnet Exposure And Authentication Hardening

Addresses findings: 1, 2, 3, 16, 17, 27, 32, 33.

Purpose:

Reduce the highest-impact remote attack surface before public v1 operation.
This phase must make the default telnet exposure local-only, add persistent
login abuse controls, remove the alias-enumeration timing oracle, make Argon2
parameters explicit, and make new-user starting security configurable.

### 1.1 Default Telnet Bind And Plaintext Warnings

Implement ADR 0013 exactly.

Required code changes:

- Change `default_bind()` in `crates/oxidebbs-server/src/config.rs` to return
  `127.0.0.1:2323`.
- Change `config/oxidebbs.example.toml` `[telnet].bind` to
  `127.0.0.1:2323`.
- Change non-interactive setup defaults in `crates/oxidebbs-server/src/setup.rs`
  to generate `127.0.0.1:2323`.
- Update config tests that assert the default bind.
- Update docs that present the default bind.
- Update the config check command to warn when bind is all-interfaces or
  non-loopback.

Required warning text:

```text
telnet bind address is reachable beyond loopback; telnet is plaintext and sends credentials and caller traffic without encryption
```

Acceptance tests:

- Config default test expects `127.0.0.1:2323`.
- Repository example config validation still passes.
- Config check on example config has no telnet exposure warning.
- Config check with `bind = "0.0.0.0:2323"` reports the warning above.

Documentation:

- Update telnet, setup, deployment, and Docker docs if they mention
  `0.0.0.0:2323` as the default.
- Public bind examples may remain only when explicitly labeled as plaintext and
  operator-chosen.

### 1.2 Persistent Authentication Attempt Store

Implement ADR 0014 exactly.

Add a schema migration that creates:

```sql
CREATE TABLE IF NOT EXISTS auth_attempts (
    scope TEXT NOT NULL CHECK (scope = 'ip' OR scope = 'alias'),
    scope_key TEXT NOT NULL CHECK (LENGTH(TRIM(scope_key)) > 0),
    failed_count INT NOT NULL DEFAULT 0 CHECK (failed_count >= 0),
    first_failed_at TIMESTAMPTZ,
    last_failed_at TIMESTAMPTZ,
    locked_until TIMESTAMPTZ,
    PRIMARY KEY (scope, scope_key)
);
```

Add repository functions in `oxidebbs-db`:

- `find_auth_attempt(db, scope, scope_key)`
- `record_auth_failure(db, scope, scope_key, now, window_minutes, lockout_minutes, threshold)`
- `clear_auth_attempt(db, scope, scope_key)`
- `is_auth_scope_locked(db, scope, scope_key, now)`

Do not store plaintext passwords. Do not store attempted passwords. Do not
store unnormalized alias scopes.

Scope keys:

- IP scope key: remote IP string as already stored in session records.
- Alias scope key: lowercase trimmed alias.

Fixed v1 policy:

- threshold: 5 failures
- window: 10 minutes
- lockout: 15 minutes

Config exposure:

Add:

```toml
[auth]
failed_login_threshold = 5
failed_login_window_minutes = 10
failed_login_lockout_minutes = 15
new_user_security_level = 10

[auth.argon2]
memory_cost_kib = 19456
iterations = 2
parallelism = 1
```

The defaults MUST match the values above.

Acceptance tests:

- Five bad attempts lock the alias scope.
- Five bad attempts lock the IP scope.
- Lockout survives closing and reopening the DB.
- A successful login clears both scopes.
- A lockout does not reveal whether the alias exists.
- Config defaults parse and repository example config validates.

### 1.3 Login Timing Equalization

Implement ADR 0014 timing rules exactly.

Required behavior:

- On alias miss, run one Argon2 verify against a process-static dummy PHC hash.
- On unparseable stored hash, run one Argon2 verify against the same dummy PHC
  hash, emit `password_hash_parse_failure`, and fail closed.
- Missing alias and wrong password both return:

```text
Invalid alias or password. Please try again.
```

Dummy PHC:

- Store a valid Argon2id PHC string as a constant in the server auth adapter.
- The dummy password string used to generate the hash MUST NOT be a real user
  password and MUST NOT be accepted for login.
- Agents may regenerate the dummy PHC only if the constant is invalid; otherwise
  keep it stable.

Acceptance tests:

- Alias miss invokes the verifier path.
- Wrong password invokes the verifier path.
- Invalid stored PHC emits `password_hash_parse_failure`.
- Visible messages for alias miss and wrong password are identical.

### 1.4 Case-Insensitive Alias Lookup Performance

Addresses finding 33 as part of the auth phase.

Implement a stored normalized alias column rather than relying on an expression
index.

Schema changes:

- Add `alias_normalized TEXT`.
- Backfill `LOWER(TRIM(alias))`.
- Enforce `NOT NULL` and uniqueness after backfill using the migration pattern
  already established in `oxidebbs-db`.

Repository changes:

- `insert_user` must write `alias_normalized`.
- `update_user_alias` must update `alias_normalized`.
- `find_user_by_alias_ci` must query `alias_normalized = LOWER(TRIM($1))`.
- New-user alias uniqueness checks must use the normalized column.

Acceptance tests:

- Case-insensitive alias lookup still works.
- Duplicate aliases that differ only by case are rejected.
- Alias update cannot collide by case.
- Existing migration tests cover upgrade from the previous schema.

## Phase 2: Control Socket And Stale Node Safety

Addresses findings: 5, 12, 35.

Purpose:

Prevent local users other than the BBS process owner from issuing control
commands, and remove reliance on manual stale-node cleanup.

### 2.1 Secure Control Socket Permissions

Implement ADR 0015 exactly.

Required code changes:

- Ensure the runtime directory is created with Unix mode `0700`.
- After binding `runtime/oxidebbs-control.sock`, chmod the socket path to
  `0600`.
- Reject clients whose peer UID does not equal the effective UID of the server
  process.
- If peer UID cannot be obtained on Unix, reject the request.
- Keep JSON request/response schemas unchanged.

Acceptance tests:

- Socket file mode is `0600` on Unix.
- Runtime directory mode is `0700` when created by the server.
- Same-UID loopback control request succeeds.
- A peer-UID rejection path is unit-tested through a helper that accepts a fake
  UID value.

Do not add a shared secret token in v1.

### 2.2 Future Web Admin Anti-CSRF Note

Finding 12 is not directly applicable to telnet sessions. Add a short note to
the sysop/admin design docs:

- local Unix control socket uses peer UID and filesystem permissions
- any future web admin interface must include CSRF and replay protection before
  it is enabled

No code change is required beyond the control socket hardening.

### 2.3 Background Stale Node Sweeper

Addresses finding 35.

Required behavior:

- Spawn one background task from server startup.
- Interval: 30 seconds.
- Action: call the existing stale-node request path for any nodes whose
  heartbeat age exceeds `stale_after_seconds`.
- Disconnect reason: `stale_node_timeout`.
- Stop the background task during graceful shutdown.

Acceptance tests:

- Runtime stale node is marked/requested for disconnect by the background path.
- Shutdown completes without leaving the sweeper task running.

## Phase 3: Door Runtime Containment And Cleanup

Addresses findings: 6, 7, 8, 9, 15, 20, 30, 34.

Purpose:

Constrain external process execution and filesystem writes before relying on
doors in v1.

### 3.1 Runner Allowlist And Runner File Safety

Implement ADR 0016 exactly.

Required config:

```toml
[doors]
allowed_runners = ["dosemu", "dosemu2"]
```

Required validation:

- Door `runner` must be in `allowed_runners`.
- Resolved runner path must be a regular file.
- Resolved runner owner must be root or the BBS process effective UID.
- Resolved runner must not be group-writable.
- Resolved runner must not be world-writable.

Acceptance tests:

- Runner outside allowlist is rejected.
- World-writable runner is rejected on Unix.
- Group-writable runner is rejected on Unix.
- Root-owned or process-owned non-writable runner is accepted in unit tests
  where metadata can be controlled.

### 3.2 Door Working Directory Containment

Required validation:

- Canonicalize `paths.doors`.
- Canonicalize `door.working_dir`.
- Reject if `door.working_dir` is not under `paths.doors`.
- Reject symlink traversal that escapes `paths.doors`.

Acceptance tests:

- Working directory under `paths.doors` is accepted.
- Working directory outside `paths.doors` is rejected.
- Symlink inside `paths.doors` pointing outside is rejected.

### 3.3 Door Time Limit Cap

Required validation:

- Accept `time_limit_minutes` only in `1..=240`.
- Reject zero, negative, and values above 240.
- Update config docs and example if any example exceeds the cap.

Acceptance tests:

- 240 minutes accepted.
- 241 minutes rejected.

### 3.4 Runtime Directory Guard

Required behavior:

- Introduce an RAII guard for per-node runtime directories.
- The guard cleans the directory on drop unless explicitly disarmed for a test
  that requires inspection.
- Use the guard in live and dry-run door execution paths after runtime
  preparation.
- Remove branch-specific cleanup that becomes redundant.

Acceptance tests:

- Cleanup runs after successful dry run.
- Cleanup runs after `build_request` or `prepare_door_run` failure.
- Cleanup runs after bridge error.
- Cleanup runs after timeout.

### 3.5 Log File Permissions

Required behavior:

- Door stdout/stderr capture files are created with Unix mode `0600`.
- Runtime node directories are created with Unix mode `0700`.

Acceptance tests:

- Unix test verifies log file mode.
- Unix test verifies runtime node directory mode.

### 3.6 Door Child Reaping

Addresses finding 15.

Required behavior:

- `terminate_child` must not leave a zombie process.
- After `start_kill`, the code must wait for child exit.
- If the normal two second wait times out, run one additional forced wait path
  that still reaps the child before returning.

Acceptance tests:

- Simulated child timeout path calls wait after kill.
- Existing door bridge timeout tests still pass.

## Phase 4: Data Correctness, Encoding, And Audit Policy

Addresses findings: 11, 13, 14, 18, 19, 36.

Purpose:

Remove avoidable correctness hazards and make operational data behavior
predictable.

### 4.1 Atomic New-User Alias Creation

Required behavior:

- Replace the `find_user_by_alias_ci` then `insert_user` sequence with an
  atomic repository operation.
- Use the `alias_normalized` column from Phase 1.
- Repository function name: `insert_user_if_alias_available`.
- Return a typed duplicate-alias error when the alias is already taken.

Acceptance tests:

- Duplicate alias returns the typed duplicate error.
- Case-only duplicate returns the same duplicate error.
- New-user flow reports the existing friendly duplicate message.

### 4.2 CP437 Encoding Policy

Addresses finding 13.

Required behavior:

- Do not silently send UTF-8 bytes to remote caller UI when CP437 encoding
  fails.
- For caller-entered strings that will be echoed or rendered remotely, reject
  unencodable characters at input time with:

```text
This BBS only accepts CP437-compatible text here.
```

- For server-generated strings, replace unencodable characters with `?` only in
  diagnostic/fallback output. Do not do this for stored caller-authored message
  subjects or bodies.

Acceptance tests:

- Message subject containing an emoji is rejected before storage.
- Message body containing an emoji is rejected before storage.
- Password input is not echoed and is not subject to CP437 rejection.
- Existing CP437 box-drawing output still encodes correctly.

### 4.3 Audit Write Policy And Visibility

Addresses findings 14 and 18.

Required behavior:

- Keep audit writes best-effort for door events, but count failures.
- Add an in-memory runtime counter named `audit_write_failures`.
- Include that counter in runtime status and control status responses.
- Add audit retention config:

```toml
[audit]
retention_days = 365
```

- Add a CLI command or maintenance function that deletes audit events older than
  the retention window. Do not auto-delete on every insert.

Acceptance tests:

- Failed audit write increments the counter.
- Control status JSON includes `audit_write_failures`.
- Retention purge deletes old rows and keeps newer rows.

### 4.4 Inline Audit UUID And Timestamp

Addresses finding 36 and partially finding 4.

Required behavior:

- Change audit insert repository code so UUID and timestamp are generated in
  the insert statement:

```sql
INSERT INTO audit_events (id, created_at, event_type, user_id, node_number, details)
VALUES (GEN_RANDOM_UUID(), CURRENT_TIMESTAMP, ...)
```

- Remove separate UUID and NOW scalar queries for audit event creation.

Acceptance tests:

- Audit event insert still returns/list events correctly.
- Login failure audit still records event type and details.

### 4.5 User Login Counter Transaction

Addresses finding 19.

Required behavior:

- Wrap `update_user_login` in the smallest available DecentDB transaction or
  single atomic statement that updates `last_login_at` and increments
  `total_calls`.
- If DecentDB serializes the single update statement atomically, document that
  in the repository test and keep the single statement.

Acceptance tests:

- Two sequential login updates increment calls twice.
- Repository test documents the atomic statement expectation.

## Phase 5: Telnet Transport And Caller I/O Performance

Addresses findings: 21, 22, 23, 24, 37, 40.

Purpose:

Reduce syscall count and per-key latency in the hot caller path.

### 5.1 Buffered TCP Reads

Implement ADR 0017 exactly.

Required behavior:

- `TcpTransport` keeps an internal read buffer.
- When the buffer is empty, read up to 4096 bytes from the socket.
- `read_byte` serves bytes from the internal buffer.
- Preserve EOF and error behavior.

Acceptance tests:

- Existing loopback tests pass.
- New TCP transport unit/integration test sends multiple bytes and confirms the
  transport can return them one byte at a time.

### 5.2 Telnet Reply Batching

Required behavior:

- Accumulate parser-generated telnet negotiation replies.
- Flush replies before caller-visible output, before blocking for more input
  when replies are pending, and before hangup.
- Do not delay caller-visible screens waiting for more negotiation bytes.

Acceptance tests:

- Negotiation sequence still emits correct reply bytes.
- Multiple negotiation events can be flushed in one write path.

### 5.3 Capability Negotiation Timeout Optimization

Addresses finding 23.

Current v1 timeout remains 300 ms unless this subtask is implemented.

Required behavior:

- End capability negotiation early when both terminal type evaluation and NAWS
  have been received.
- End immediately on real caller data and preserve that data.
- Keep 300 ms as the maximum timeout.
- Make the timeout configurable only if needed after tests; otherwise keep the
  constant.

Acceptance tests:

- SyncTERM plus NAWS completes before the full timeout.
- No-response client still falls back after the timeout.

### 5.4 Menu Newline Drain Optimization

Addresses findings 24 and 37.

Required behavior:

- Remove the two 5 ms timeout polls from `drain_line_ending_after_menu_key`.
- Replace them with an input-session pending-byte/parser buffer check.
- If no byte is already pending, do not wait.

Acceptance tests:

- `N\r` still drains the newline before new-user prompt.
- `N\rX` still preserves `X`.
- A single `N` no longer waits for drain timeouts.

### 5.5 CP437 Output Allocation Reduction

Addresses finding 40.

Required behavior:

- Do not change external behavior.
- Reduce repeated small allocations in hot prompt output by reusing a buffer
  where straightforward.
- Do not introduce a new dependency.

Acceptance tests:

- Existing CP437 encode tests still pass.
- Existing telnet smoke test still passes.

## Phase 6: Message And Connection Path Performance

Addresses findings: 25, 26, 28, 29.

Purpose:

Reduce database round-trips and per-connection cloning once security work is in
place.

### 6.1 SQL-Side Message Visibility Filtering

Required behavior:

- Add repository function that lists only messages visible to a given user
  security level.
- Filtering must include message visibility and area read security.
- `run_messages_flow` must call the filtered repository function instead of
  fetching every message then filtering in Rust.

Acceptance tests:

- Low-security user does not receive high-security area messages.
- Hidden/deleted messages remain filtered as current behavior requires.
- Existing message flow tests pass.

### 6.2 Batch Message Author Aliases

Required behavior:

- Replace per-message `find_user_by_id` calls with one batched alias lookup.
- Build `HashMap<user_id, alias>` once per message list display.
- Unknown/missing users still display `Unknown`.

Acceptance tests:

- Listing messages by multiple authors displays correct aliases.
- Missing author still displays `Unknown`.

### 6.3 Avoid Per-Connection Deep Config Clone

Required behavior:

- Store `Arc<OxideConfig>` in the server accept loop resources from startup.
- Do not clone `OxideConfig` per accepted connection.
- Keep caller tasks owning/cloning only `Arc<OxideConfig>`.

Acceptance tests:

- Existing telnet runtime smoke passes.
- Server startup tests still pass.

### 6.4 Cache Message Area List During Message Flow

Required behavior:

- Load the enabled message area list once per entry into `run_messages_flow`.
- Reuse it while the caller remains in the message flow.
- Refresh it only when the caller exits and re-enters messages.

Acceptance tests:

- Area selection behavior remains unchanged.
- Back/exit behavior remains unchanged.

## Phase 7: Low-Risk Follow-Ups And Load-Test Notes

Addresses findings: 4, 10, 31, 38, 39.

Purpose:

Record lower-priority concerns so they are not lost, while keeping earlier
phases focused.

### 7.1 Login Failure Audit Write Amplification

Finding 4 is mostly reduced by Phase 1 rate limiting and Phase 4 inline audit
UUID/timestamp insertion. No separate process-side UUID cache is required.

Required verification:

- After Phase 1 and Phase 4, run a test or benchmark that simulates repeated
  login failures and confirms the rate limiter bounds audit writes.

### 7.2 Hard Link Staging Panic Leak

Finding 10 is considered handled by Phase 3 runtime directory guard.

Required verification:

- Add one test that forces failure after staging and confirms runtime cleanup.

### 7.3 Config-Driven ANSI Terminal Allowlist

Finding 31 is intentionally deferred.

Current policy remains the hardcoded allowlist from ADR 0013 and
`design/TELNET.md`.

Do not add config-driven terminal allowlists unless the user explicitly requests
that after v1 security work.

### 7.4 CP437 Lookup Table Micro-Optimization

Finding 38 is not a v1 target.

No action unless profiling shows CP437 lookup dominates runtime.

### 7.5 Connection-Level Backpressure Load Test

Finding 39 is behavior to validate, not a requested change.

Required load-test note:

- Add a manual or automated load test that connects `max_connections + 1`
  callers.
- Confirm the extra caller receives the busy rejection message and all accepted
  node slots remain stable.

Do not change accept/rejection behavior unless that test fails.
